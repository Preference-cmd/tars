# Session assembly and execution

This page describes the current implementation as of 2026-11-25. Design and acceptance records live outside the public repository.

## 1. Creating and reopening

```text
CLI arguments → SessionDefinition + initial Context → PreparedCreate
  → SessionHost registers opening + starts independent supervision
  → persistent instance takes the stable file lock → reads and validates the latest complete record
  → assembly resolves credentials once and freezes gateway / runner / execution options
  → create: confirms initial revision 1; reopen: adopts the existing revision
  → publishes a ManagedSession bound to this SessionTarget
```

[Host](../crates/core/src/application/host.rs) registers and starts the supervision task while holding the directory lock, and concurrent calls with the same ID connect to the same instance. The ConversationId and initial commit_id for create are frozen by the synchronous PreparedCreate; a waiting caller leaving does not change them. A read/assembly failure followed by the task stopping removes the opening; an initial commit failure keeps a lookup-able InitializationBlocked with the original operation and publishes no committable view.

[Definition](../crates/core/src/definition/types.rs) is saveable data; only [assembly](../crates/core/src/assembly/provider.rs) resolves environment references. The definition is frozen in a live instance, and reopening resolves the same reference again; a connection never captures a particular WorkRef. Each work still receives options with its own identity, control and frozen policy. The application session entry ([entry](../crates/core/src/application/entry.rs), exposed via [ManagedSession](../crates/core/src/application/managed.rs)) owns the instance's `PermissionHub`, mode switching, approval routing, and command rules, while the low-level `Session` ([owner](../crates/core/src/session/owner.rs)) owns only materials and work execution without holding permission state or `ApplicationError`. Construction and reopening send no model request.

## 2. Acceptance and execution

[ManagedSession::submit](../crates/core/src/application/managed.rs) first compares the complete arguments against the underlying unique request-key table, then checks the lifecycle and save gate. A retained key with the same arguments returns the original receipt, while different arguments return Conflict; a new key rejection returns the original request. New-work acceptance and the host active-slot registration happen inside the same application gate, so a worker that finishes first cannot let T2 pass the save.

The low-level [SessionHandle](../crates/core/src/session/handle.rs) allocates the TurnId, atomically appends the input, saves a copy of the original request, marks the input blocks as the work's protected input for compaction (cleared when the work ends) and hands the Context to the worker. Each instance has at most one active work and no background submission queue. The work deadline starts at acceptance and covers per-work assembly and execution; it does not cover opening, stdin or disk I/O.

The [Worker](../crates/core/src/session/worker.rs) checks control, calls per-work assembly, and then hands off to the Causa public facade's `TurnRunner::run_streaming`. Causa handles the model/tool loop of one work and returns the actual Context, the typed TurnResult and the uncommitted ToolBatch; it does not own TARS directories, files or work history. Product assembly defaults to an empty workspace tool catalog and can bind up to ten built-in tools defined by `BuiltinTool`: the seven explicit workspace tools (`list_directory`, `read_file`, `search_text`, `find_files`, `write_file`, `edit_file`, `run_command`; platform limits of the command tool are in [Workspace tools](workspace-tools.md)), `recall` (automatically bound for persistent sessions), `load_skill` (automatically bound when skills are enabled and at least one valid skill is discovered), and opt-in `run_code` (when enabled and at least one eligible read-only tool is present). Every built-in tool exposes its `ManagedTool` adapter through Causa's `Tool::metadata()`, and `McpServerSource` attaches each `McpToolAdapter` to its `ToolDescription::metadata`; per-work assembly wires the single `before` `ToolPolicyProcessor` backed by the instance's `PermissionHub`. Root resources are shared within an instance, while stateless tool wrappers and the ToolReporter are created per WorkRef, and approved preflight payloads travel per call inside Causa `CallAttachments`. Tool materials in an old Context never trigger a rerun of old tools.

## 3. Finished and Saved

The low-level supervisor waits on both normal and exceptional paths for that work's supervised file closures to actually exit, freezes the reliable tool state, then returns the materials and batch and publishes the original `Arc<WorkResult>`. Dropping a tool future requests that the operation stop but cannot replace real task reclamation. The host's [independent supervision path](../crates/core/src/application/supervisor.rs) waits until real materials are available, advances the MaterialVersion and fixes this immutable save operation.

```text
submit → Dirty → original WorkResult::Finished → freeze returned materials → Saving
                                                       ├─ confirmed → Saved → T2 can be accepted
                                                       └─ error → SaveBlocked
                                                                    ↓ retry_save
                                                               confirm/retry original commit
```

Save I/O runs in blocking tasks with a concurrency limit and does not hold the synchronous coordination lock. Waiters, cancellation, replay and observation remain responsive. Saved is a persistent fact; Finished only describes execution. A failed save never turns Completed into an execution failure; retrying never reruns the model. A transient instance stays NotTracked and still releases the active gate only after the materials are returned.

`read_materials` returns a copy of the actual idle materials with a version. `edit` validates against that MaterialVersion as the baseline and replaces all blocks in one step, rejecting old versions, old instances, Busy or unhandled saves; a valid persistent edit fixes a new snapshot and saves it, and arbitrary re-entrant edit callbacks are not accepted.

Material handling after interruption reuses the same edit/save gate: `inspect_repair` inspects read-only, `plan_repair` builds a non-rewritable candidate that passed protocol validation, and `apply_repair` checks the material version, open instance and original batch availability and commits once. take/forget invalidate existing plans. New-key pairing admission failure returns the original input without registering work, and retained-key replay still takes precedence. CLI/TUI operations and the original-result retention scope are in [Continuation after interruption](session-continuation.md).

## 4. SQLite v3 commits, Transactional Outbox, and legacy import

[Store](../crates/core/src/store/sqlite.rs) is the concrete SQLite v3 backend inside the core (`rusqlite` `bundled`, `<store>/tars.db` in WAL mode with `synchronous = NORMAL`, `foreign_keys = ON`, `busy_timeout = 5000`, `user_version = 1`, and per-session OS advisory locks under `<store>/locks/<uuid>.lock`). Data is normalized across 7 tables: `sessions`, `agents`, `operations`, `agent_events`, `history_records`, `artifacts`, and `workspace_trust`.

A session saves `ConversationId`, `revision`, `last_commit_id`, `policy_json` (`tars-session-v2.4`), `entry_agent_id`, optional `title`, `updated_at_ms`, per-agent `AgentDefinition` (including frozen `prelude` configuration), `Context`, `history_index_json`, and `usage_json`; it accepts only canonical UUID identifiers and never concatenates arbitrary input into filesystem paths. `title` is taken from the first non-blank line of the first real user message—skipping `tars:prelude:*` (including `tars:prelude:update:*`), `tars:compaction`, `tars:skill`, and `tars:task-notification` blocks—trimmed with internal whitespace collapsed to single spaces and truncated to at most 80 Unicode scalar values; it is set on the first commit with a real user block and never changes afterwards; if that message has no text, the session stays untitled. `updated_at_ms` records Unix milliseconds on every commit and monotonically advances using `max(now, previous updated_at_ms)`. The session creation timestamp `created_at_ms` is derived directly from the UUIDv7 `ConversationId`. The definition's `prompt_cache: bool` (defaulting to `true`) controls whether `CacheDirective::StablePrefix` is set on turn run options and compaction brief requests.

The writer holds the stable OS lock file `<store>/locks/<uuid>.lock` from open until close; every in-flight blocking operation also holds it. Every write runs inside a `BEGIN IMMEDIATE ... COMMIT` transaction behind a bounded `spawn_blocking` / `Semaphore` gate. Single-agent commits and multi-agent **Transactional Outbox** updates (`commit_outbox`) atomically persist updated agent `context_json` / `history_index_json` / `usage_json`, terminal `operations` rows (`status`, `outcome_json`, `result_text`, `result_bytes`, `finished_at_ms`), newly emitted or `delivered` / `dropped` `agent_events`, and the incremented `sessions.revision`. When confirmation is lost, the writer resolves the original `last_commit_id` idempotently (`resolve_commit`): only an unchanged baseline with continuous write lock proves the commit was not applied, while an advanced revision or conflicting payload keeps the unconfirmed/blocked state without generating a new identity or force-overwriting.

Lock-free read-only operations (`list`, `inspect`, `inspect_agent`, `read_saved_history`, `read_agent`) open `tars.db` in read-only WAL mode (`SQLITE_OPEN_READ_ONLY`) without acquiring `<uuid>.lock`, so inspection never contends with an active session writer. Corruption or unsupported formats are isolated per session rather than falling back to defaults.

History rewrite records (`tars-history-v1.2`, `kind`: `summarize` | `merge` | `micro-compact`) and spilled tool outputs (`artifact:<artifact id>`) are stored per `(session_id, agent_id)` inside the SQLite `history_records` and `artifacts` tables rather than per-session subdirectories. `micro-compact` rewrites go through the same `commit_rewrite` path as `summarize` and `merge`, folding eligible old or superseded `ToolResult` blocks into single-line stubs pointing at `<record id>/<orig block id>` or inheriting an existing `artifact:<artifact id>`; conversation expansion restores micro-compacted tool results in place without emitting a divider (`MicroCompacted(record_id)`), and later `summarize` rewrites expand recursively across `summarize -> micro-compact`. Opening removes orphan `history_records` and `artifacts` rows under the write lock (scanning both live Context and `history_records` for spilled outputs, `ContentPart::Media`, and `ToolResult.media` references so active or archived media is preserved); missing or corrupt referenced records are reported during conversation expansion. Legacy `tars-session-v2.4` JSON files on disk are never overwritten or silently upgraded: `tars session export-materials` remains available for extracting standalone Context (plus sidecar `.media/` blobs when managed images are present), and `tars session import-legacy` explicitly imports a validated `tars-session-v2.4` JSON record (together with its `.history/` and `.artifacts/`) into SQLite as a single-root-agent session with its original definition and Context preserved (older `tars-session-v2.3` / `tars-history-v1.1` and earlier formats remain rejected with `StoreError::UnsupportedFormat`). Stored Context decoding across session rows, material files, and exports passes through [`material::vocabulary`](../crates/core/src/material/vocabulary.rs).

### Multimodal image persistence, integrity, and protocol wiring

User-submitted raster images (`PNG`, `JPEG`, `GIF`, `WebP`, verified strictly by file-header magic bytes in [`media`](../crates/core/src/media.rs); bounded to `MAX_IMAGE_BYTES = 5 MiB`, `MAX_IMAGES_PER_MESSAGE = 8`, and `MAX_SESSION_MEDIA_BYTES = 64 MiB` deduplicated raw bytes per session) are content-addressed as `media:sha256:<64-lowercase-hex>` with sanitized basename metadata (`MediaRef.name`) and staged in the session's in-memory `MediaVault` (`MediaResolver`):

- **Zero-migration SQLite atomic commit**: Keeping `user_version = 1`, `saving::save` / `Writer::commit` writes referenced `media:sha256:*` image blobs into `artifacts(session_id, agent_id, artifact_id, content)` via `INSERT OR IGNORE` inside the same `BEGIN IMMEDIATE` transaction **after** `upsert_session_and_entry_agent`. This prevents first-turn foreign-key races, deduplicates identical images within a session, leaves zero orphan BLOBs when transient or unsaved turns abort, and cascades cleanly on `delete_session`.
- **Fail-closed reopen & MCP media resolution**: Reopening a session preloads all `media:sha256:*` blobs referenced by live Context or `history_records` into `MediaVault`, re-verifying SHA-256 digests, magic bytes, and size bounds and failing closed if any referenced BLOB is missing or tampered with (before any model request is sent). `MediaVault` also binds the session's `HistoryStore` so MCP `ToolResult.media` references (`artifact:<uuid>`) resolve from `artifacts` on subsequent model rounds and reopens. `SavedSessionRecord::validate`, `material::references`, and `repair::inspect` accept verified `media:sha256:*` and `artifact:<uuid>` references while rejecting unvalidated URLs, paths, or missing blobs.
- **Protocol inline ceiling & compaction omission**: Main-conversation model gateways (`assembly::protocol_gateway`) wire `MediaVault` and set `GATEWAY_INLINE_IMAGE_LIMIT_BYTES = MAX_IMAGE_BYTES + 3` (`5_242_883` bytes) so exact `5 MiB` (`5_242_880`-byte) images are delivered inline without degrading due to Causa's base64 padding estimate (`data_base64.len() * 3 / 4`). By contrast, the compaction summary gateway intentionally omits `MediaResolver` so summarization degrades image blocks to lightweight text placeholders without re-uploading raw image bytes, while preserving the archived media BLOBs in `artifacts` for `history_records` and post-compaction reopen.

### Multi-agent coordination and three-plane event bus

Each open `ManagedSession` owns a [`SessionCoordinator`](../crates/core/src/application/coordinator/engine.rs) and a [`BackgroundTaskRegistry`](../crates/core/src/events/background.rs) coordinating all agents (the root entry agent and spawned child agents) across three planes without polling:

1. **Plane 1 — Persistent causal mailbox (`agent_events`)**:
   - **Mid-turn injection (target `Running`)**: Inside [`CompactionPreparer::prepare`](../crates/core/src/compact/preparer.rs), micro-compaction and LLM summary evaluation always execute **first**, and pending `agent_events` are drained afterwards and appended as `Role::User` blocks (`BlockMeta.source = "tars:task-notification"`, `<task-notification ...>` XML envelopes, 8 KiB inline cap with `read_agent` pagination pointers for longer outputs). Events remain `pending` in SQLite until the target agent's turn Context commits in the same `commit_outbox` / save transaction, guaranteeing zero loss and zero duplicate delivery across crashes.
   - **Idle reactive wakeup (target `Idle`)**: `SessionCoordinator` triggers an automatic wakeup only when all **7 admission guards** pass: (1) session lifecycle is `Open`; (2) session is not `SaveBlocked`; (3) target agent is idle (no active run, no pending save, not compacting); (4) target agent has no unpaired tool batch / pending repair; (5) target agent is runnable (valid credentials/definition); (6) `auto_wakeups_in_cycle < max_auto_wakeups` (default `16`, reset on each explicit user submit; overflow downgrades remaining events to `deliver_on_next_turn`); (7) at least one `wake_if_idle` event is queued. A `50 ms` sibling debounce coalesces concurrent sibling completions (`coalesce_key` keeps the latest payload), while the final active sibling wakes immediately (`0 ms`).
   - **Reopen invariant**: Reopening a session **never** auto-executes pending events or old work: stale active operations from a prior crash are reconciled to `Interrupted`, and pending `wake_if_idle` events are downgraded to `deliver_on_next_turn` so they wait for explicit user input or read-only inspection.
2. **Plane 2 — Non-blocking observable bus (`SessionEvent`)**: `ManagedSession::subscribe_events()` returns a `broadcast::Receiver<Arc<SessionEvent>>` emitting `SessionLifecycleChanged`, `AgentRegistered`, `OperationStateChanged`, `InboxEventChanged`, `AgentProgress`, and `BackgroundTaskChanged`; lagging UI/CLI consumers recover from authoritative snapshots.
3. **Plane 3 — Interactive approval hub (`ApprovalsHub`)**: Child and background tool confirmations route through the shared `ApprovalsHub` tagged with `(agent_id, agent_name, operation_id)` (`ApprovalOrigin`) and cleanly abort pending confirmation channels when the child operation or parent work is cancelled.

`BackgroundTaskRegistry` tracks active `Finite` tasks (`TaskLifecyclePolicy::Finite { on_parent_complete }`) and provides `wait_background_tasks_settled()`, `wait_settled()` / `wait_settled_after()`, and cascading `cancel_all_active()`. Explicit parent cancellation, deadline expiry, or failure cascades across all non-terminal descendants (emitting `suppress_wake` to prevent zombie wakeups); normal parent completion honors each operation's `on_parent_complete` (`continue` or `cancel`); closing a session (`Save` or `DiscardLocal`) cancels and settles all participants regardless of `continue`.

## 5. Closing, faults and batches

The host's close checks the complete SessionTarget, marks Closing, closes new acceptance and requests cancellation, then waits for the real worker and I/O. Save releases after confirming the latest materials; on save failure the owner/write access is kept and a retry can continue closing. DiscardLocal also waits for in-flight writes to stop and only confirms the original pending commit without writing again. The returned CloseOutcome distinguishes Applied, NotApplied, NotSubmitted and Unresolved; an unconfirmed outcome keeps the original structured error, and close must never be treated as the record not existing. It does not roll back committed records. An opening can also be closed through its lookup target, in which case the original waiter never receives a committable handle; conflicting policy requests in progress are refused, and a blocked close with no in-flight operation may explicitly switch to DiscardLocal.

An old ManagedSession can only observe the facts it retained and never follows a redirected ConversationId. Dropping a view does not close the owner; dropping the last external host requests supervised cleanup and cannot replace an explicit await. Runtime or process exit does not guarantee a clean settling.

An owner/worker fault isolates new work, waits for confirmable task stops and keeps the fault and lock until it is explicitly handled. ContextUnavailable is reported truthfully, and an old disk version is never disguised as the materials returned by this run. The local file lock has no lease expiry while OS handles stay alive; external lock revocation and cross-host shared execution are not supported.

`SessionHost::take_uncommitted_tool_batch(target, work)` takes the original U once from the original owner inside the same coordination boundary, with no await, copy or tool execution. Arcs of observed results stay unchanged. forget is refused while an associated save is unhandled; after forget the request keys, terminal states and unclaimed batches are released while existing Arcs remain valid. An entry point that needs U must claim it before the final close; the Store never saves U additionally.

## Renaming, deleting, and forking

- **Rename (`SessionStore::rename_session`, `ManagedSession::rename`, `SessionHost::rename`)**: Titles are normalized and validated via `validate_session_title` (`MAX_SESSION_TITLE_CHARS = 160` Unicode scalar values): `Some(raw)` trims leading and trailing whitespace and rejects blank strings or control characters (`char::is_control`), while `None` explicitly clears the title and suppresses auto-derived titles (`saving::next_metadata`). On an open `ManagedSession`, `rename` records `desired_title` and immediately triggers a save when persistent and idle, or reconciles across in-flight turns, active saves, compaction, and `ClosePolicy::Save` without being overwritten by an earlier commit's completion. Unopened sessions acquire `<locks_dir>/<id>.lock` (`StoreError::Occupied` → `ApplicationError::SessionLocked` if held), verify the session exists (`StoreError::NotFound` → `ApplicationError::NotFound`), update `sessions.title`, increment `sessions.revision`, write a new `last_commit_id`, and monotonically advance `updated_at_ms` inside `BEGIN IMMEDIATE`.
- **Delete (`SessionStore::delete_session`, `SessionHost::delete`)**: `SessionHost::delete` refuses sessions currently open in the same host (`ApplicationError::SessionActive`). `SessionStore::delete_session` acquires the session's exclusive OS lock (failing closed with `ApplicationError::SessionLocked` if held by another process), runs `UPDATE operations SET parent_operation_id = NULL WHERE session_id = ?1` inside `BEGIN IMMEDIATE` before `DELETE FROM sessions WHERE session_id = ?1` so nested multi-agent operations (`depth >= 2`) cascade cleanly across `agents`, `operations`, `agent_events`, `history_records`, and `artifacts` under `PRAGMA foreign_keys = ON`, leaves `workspace_trust` untouched, and best-effort removes `<locks_dir>/<id>.lock` after releasing the lock.
- **Fork (`SessionStore::fork_session_with_lock_check`, `SessionHost::fork`)**: Creates a physically isolated clone under a fresh UUIDv7 `new_id` containing the entry agent's `SessionDefinition`, `Context`, `history_records` (deserializing each `HistoryRecord`, rewriting `conversation_id = new_id`, checking `MAX_HISTORY_BYTES`, and re-serializing), and `artifacts` (including all persisted `media:sha256:*` images and `artifact:<uuid>` blobs). Resets `revision = 1`, `agents.material_revision = 1`, and `usage = None`; sets `title` to the validated explicit title or `<source_title> (fork)` bounded to `MAX_SESSION_TITLE_CHARS` (staying `None` if untitled); and downgrades a runtime `full-access` mode to `ask` when `definition.initial_permission_mode() != PermissionMode::FullAccess`. Non-entry child agents, `operations`, and `agent_events` are not cloned, so deleting the source session does not affect the fork or its inherited media. Open sessions must be persistent, idle, cleanly saved (no pending/in-flight/blocked save or uncommitted metadata/settings), without active child operations or compaction, and pass `repair::admission_check` (`ForkGuard` + `writer_gate` block concurrent mutations and closes during the fork); unopened sessions fail closed with `ApplicationError::SessionLocked` if externally locked.

## 6. CLI consumers

`session create` only creates and confirms the initial SQLite record (and accepts `--trust-workspace-agents` to trust `<workspace>/.tars/agents/*.md` in `workspace_trust`). `session run ID` reopens the saved definition, submits new work (accepting repeatable `--image <PATH>`, up to 8 images, with or without text input), waits for the root turn, all `Finite` background tasks, and any triggered reactive wakeups (`wait_settled` / `wait_settled_after`) to converge, waits for the independent save result and then closes; provider/model cannot be overridden transiently, and `--trust-workspace-agents` can explicitly record trust for workspace agent presets on reopen. `session compact ID` compacts manually through the session's model and waits for the save. `session rename ID (--title <text> | --clear)` updates or clears an unlocked session's title; `session delete ID` permanently deletes an unlocked session while preserving `workspace_trust`; `session fork ID [--title <text>]` creates an isolated fork at revision 1 (all three support `--json`). `session export-materials` exports detached Context without overwriting an existing destination, and when `media:sha256:*` images are referenced, writes verified `<sha256>.bin` sidecar blobs into `<output>.media/` and reports the sidecar directory and count in both text and `--json` output (re-import via `material::load_with_media` fails closed on missing, corrupt, or hash-mismatched sidecar files, while default `material::load` without sidecar continues rejecting managed media references).

`session history ID [--agent <id-or-name>]` inspects the saved session via a lock-free WAL read-only query without resolving credentials or locking, printing the expanded conversation for the root entry agent (or a specific child agent matched by `agent_id` or unique `name`) with block status (`original`, `summarized (record id)`, `micro-compacted (record id)`, `unreadable (record id)`), rendering sanitized single-line media summaries for user `ContentPart::Media` and `ToolResult.media` (`[media <mime> <name> (<ref>)]`), and marking tool results carrying spilled or micro-compacted references (`artifact:<artifact id>` or `<record id>/<orig block id>`); `--json` prints one block per line preserving native multimodal structures, `--last N` reads only the newest `N` blocks on demand, and an unreadable record exits 1 after printing what it could. `session show ID [--agent <id-or-name>]` likewise runs lock-free against WAL without resolving credentials or mutating files: without `--agent`, it reports session metadata, prelude/skills/agents summary, context usage, history record count, retained-work occupancy, usage statistics, and the `agents` roster; with `--agent`, it reports that agent's descriptor, material revision, operations, pending events, and usage (`--json` includes all fields structured). `session list` prints id, last-activity time, status, and title newest first (`--json` includes `title`, `created_at_ms`, and `updated_at_ms`) without credential resolution. `session import-legacy --record FILE --store DIR` explicitly imports a validated `tars-session-v2.4` JSON record (alongside its `.history/` and `.artifacts/`) into SQLite without modifying the source JSON file. All `session` subcommands require an explicit `--store`.

On save failure the CLI keeps the original execution status/text and additionally outputs `save_error`; according to the user's choice it exports a random, non-overwriting recovery Context and then exits 1. `recovery_error`, `close_error` and `close_outcome` are reported separately; a recovery file contains the actually returned materials, not the original work table or uncommitted content. After Ctrl-C during execution or background convergence, `cancel_all_active()` cascades cancellation across the root turn and all active child/background tasks, then waits for return and save; a second Ctrl-C during the save wait stops waiting, exports the actual Context and exits with an error.

`tars run` creates a transient host (with `retained_work_capacity = 17` to accommodate 1 initial turn plus up to 16 reactive wakeups), converges finite background tasks and reactive wakeups before exiting, accepts repeatable `--image <PATH>` (supporting text + images or image-only turns), and supports `--load`/`--save` (transient runs cannot persist trust for `.tars/agents/*.md`, so untrusted workspace agent presets remain ignored with a stderr notice). When `context_window` is known, a transient run installs only a temporary frame-trimming preparer that drops older intervals on a copy of over-window request frames without modifying Context or spilling tool outputs; when `context_window` is unknown, no trimming preparer is installed.

## 7. Usage statistics

The counting gateway sits inside `StreamRetryGateway`, so every request sent to the endpoint is one call, pre-first-delta and pre-`Done` mid-stream retries included (while `UsageTrackingGateway` sits outside and updates only from the final `Done`). A call either succeeds or fails (an invoke error, a stream error, or a stream that ends without completing); a successful call whose response carried no usage counts as "without usage". Failed calls add no tokens. Conversation calls and compaction summary calls are counted separately, and the total is their sum.

The four token counts do not overlap: `input_tokens` is uncached input, then cache read, cache write and output. Prompt = input + cache read + cache write; total = prompt + output. Reasoning is part of output and is never added to a total. The cache hit rate is cache read divided by prompt, taken only over the calls that reported cache reads.

A work's statistics hold its calls, its model rounds (successful conversation calls) and its last call; they exist only in memory and are returned in the `usage` field of `tars run --json` and `session run --json`. The session's statistics add up all works plus the input rounds (works that entered the runner, whether they completed, failed or were cancelled) and the last call; `session show` and the TUI `/status` show them, and they are saved with the record as described in [section 4](#4-sqlite-v3-commits-transactional-outbox-and-legacy-import).

A count that no call reported is `null` in JSON and "not reported" in text, never 0: input, output, prompt and total when no successful call reported usage, and cache read, cache write or reasoning when every call that reported usage left that count out. These rules live in `UsageFigures` in [`usage`](../crates/core/src/usage.rs).

## Transient streaming observation

`SessionHandle::subscribe_progress` and `ManagedSession::subscribe_progress` return this instance's broadcast receiver. Callers that need to observe new work subscribe before submit; each WorkProgress carries the WorkRef, InvocationId and ModelStarted, body Text, ModelOutputReady, Tool, or Compaction (including temporary frame trimming) updates. When `StreamRetryGateway` performs a pre-`Done` mid-stream retry on a conversation stream (`max_model_attempts > 1`), it re-emits `ProgressUpdate::ModelStarted` for that `InvocationId` so subscribers reset any partial draft instead of concatenating attempts. Current limits, Lagged and truncation semantics are in [Current implementation](README.md#streaming-observation). The original `TurnRunOptions::observer` is composed with the call and never silently replaced.

These events are losable transient observations with no work-history or reopen-recovery meaning, and they are not material-editing instructions. Reliable WorkResult is still kept by the original work table; the synchronous observer does not wait for UI consumption. Only the Context returned by Causa enters the original save flow; text fragments before cancellation/EOF/error are never padded into complete model output. Model output being complete, work being terminal, and materials being saved remain distinct facts.
