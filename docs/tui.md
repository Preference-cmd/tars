# Native terminal interface (TUI)

`tars-tui` is the native terminal interface library built on Ratatui + Crossterm, launched directly by the unified `tars` binary when run on an interactive terminal without a CLI subcommand (`tars` / `tars [interactive options]`), and shares `SessionHost` and the [TOML configuration](configuration.md). Session creation/opening, zero-config startup and first-run onboarding, `/doctor` diagnostics, `/init` workspace initialization, current materials, temporary streaming body, final result, multi-line input, cancellation, saving and recovery operations are wired; workspace tools (including the write confirmation panel, `/mode` command and `Shift-Tab` mode switching) are wired; MCP is wired through the `mcp.json` configuration with form selection, definition snapshots and runtime tools, the status line reports servers that did not start and tools that were skipped after a session is opened, and a saved full-access that was downgraded to ask on reopen is also reported, while MCP calls support execution, confirmation and rejection according to the permission mode. Long-session compaction is wired: the conversation expands the replaced material above the current materials, reads history records lazily while scrolling up, folds the current summary, and exposes `/auto_compact`, `/compact` and `/summary`. Startup checks the sandbox backend and the external `rg` before the conversation screen, so search availability is known before the first request (see [Startup check](#startup-check)). There is no GUI or packaged installer distribution. Commands run through the built-in `run_command`, described in [Workspace tools](workspace-tools.md). Build and dependency baselines are in [Current implementation](README.md).

The command confirmation panel shows the full command, working directory, deadline, network policy and "workspace writable, `.git` hooks and configuration read-only, credentials unreadable", and when the command is parseable shows the suggested rule prefix and a prefix-risk note; a sandbox-outside request instead shows a prominent "not in the sandbox: whole machine readable/writable, network reachable, credentials readable", the model's justification, and a warning that any saved rule includes `outside_sandbox = true`, no longer showing the session's network setting. Confirmations originating from a delegated child agent prefix both the waiting notice and the panel header with `[agent: <name>]` (control-character-escaped at display time, while root-agent approvals omit the prefix). When opening or creating a session with an untrusted or externally modified `<workspace_root>/.tars/permissions.toml` containing `allow` rules, a trust prompt displays all pending `allow` rules (highlighting `[OUTSIDE SANDBOX]`) and a unified diff against the previously trusted version, guarded by the same 0.5-second accidental-key window (`Enter`/`y` trusts, `n`/`Esc` declines while keeping `deny`/`ask` active). Likewise, when untrusted or modified `<workspace_root>/.tars/agents/*.md` presets are present, a workspace agents trust prompt lists the pending preset names and diagnostics under the same 0.5-second accidental-key guard (`Enter`/`y` persists trust in SQLite `workspace_trust` and refreshes `<available_agents>`, `n`/`Esc` keeps workspace presets excluded). `/status` adds `Prompt cache: on | off`, `Code execution: on (...) | off`, `Commands: ...`, showing the sandbox backend and each capability dimension (with the reason when unavailable), plus `Search: ready (rg <version> at <path>)` or `Search: unavailable: <reason>`, the `Sandbox:` brief from the startup check, and a `Usage:` section with live session call counts, input rounds, token totals, conversation/compaction breakdowns, and last call details (see [Usage statistics](session-lifecycle.md#7-usage-statistics)). The new-session form shows a read-only `Command: network ... · timeout ...` line when Tools includes `run_command`; it is not an input field and cannot be edited. The line disappears once the command tool is disabled.

## Startup check

After the terminal is initialized and before the conversation screen, the TUI runs two checks as blocking background jobs under one bounded deadline: the platform sandbox probe and the external-tool resolution from `[external_tools]`. The splash shows a row for each (`Sandbox`, `ripgrep`) with core's own short report or reason; the checks never block terminal input and a stuck probe is abandoned at the deadline.

- All ready: the main screen opens directly, with no question and no unavailable line.
- Sandbox unavailable: the main screen opens with `search unavailable: <reason>` in the footer, and no download is offered because search needs both.
- `rg` unavailable and configured as `auto` or `managed` (on a platform with a pinned release): the splash asks `Download ripgrep 15.2.0 (about 2 MB from github.com/BurntSushi/ripgrep) and install it for search? [y/N]`. Under `auto`, if a valid `rg >= 14` is already on `PATH` and no corrupted managed file is on disk, TARS enters immediately without prompting to download. For 0.5 seconds after the question appears every key is ignored, the same window as the confirmation and repair panels. `y` shows a downloading state, installs the pinned release through the core, re-resolves the check and enters the main screen; `n`, Esc, a failed install or the deadline enters with the reason.
- `rg` unavailable and configured as `system` or an absolute path (or on a platform without a pinned release): no download is offered; the main screen opens with the reason.

The resolved tools are attached to the session host this TUI opens, so `search_text` runs exactly the checked executable; a declined or failed check still lets sessions open and rejects search calls with the core reason. `/status` keeps the `Search:` and `Sandbox:` lines for the running session. The check and the consent gate live in core (`tars_core::external_tools`, `tars_core::sandbox`); the TUI only presents progress and collects the answer, and the 15-second startup deadline is a presentation bound, not a core contract.

```sh
cargo build -p tars-cli --locked
# Zero-config launch (uses ~/.tars/data or $TARS_HOME/data and opens first-run setup if unconfigured):
./target/debug/tars
# With explicit configuration:
./target/debug/tars --config /path/to/config.toml
# Isolated without global config (--store is required with --no-config):
./target/debug/tars --no-config --store ./tars-data
```

Both stdin and stdout must be interactive terminals (non-TTY bare `tars` prints unified help and exits 0; non-TTY with interactive flags such as `--no-config --store DIR` exits 1). At least 30×12; below that size the whole screen shows only a resize notice. When a confirmation request is pending, at least 30×19 is needed to show the panel and accept allow/reject keys; when smaller, only the resize notice is shown and Esc or Ctrl-C still cancels the round. In a short window forms show the current field at a time, with Tab switching.

When launched with configuration enabled (`!no_config`) and no loaded `config.toml`, no active preset, and an empty store, the TUI automatically opens the **Welcome to TARS · First-run setup** onboarding panel (`Provider` cycled with `←`/`→`, `Model`, `API key env var` with a live `[set]`/`[not set]` indicator that never echoes values, optional `Endpoint`, `Max tokens` auto-filled to `8192` for `anthropic` when untouched, and `Workspace` prefilled with the current working directory). Confirming (`Enter`/`Ctrl-S`) validates fields and workspace directory before writing `~/.tars/config.toml` atomically with `CreateNew` (never overwriting an existing config and storing only the env var name), updates the host, and immediately creates and opens a session bound to the workspace and dynamic initial tools (`default_tools_for_sandbox` reusing the startup sandbox probe when present, falling back to `default_tools_for_current_platform()`: all 7 tools on macOS or on Linux when `bwrap` succeeds, and the 5 non-sandboxed tools on Linux when `bwrap`/userns is unavailable). Pressing `Esc` skips onboarding without writing any files.

Creating a session via `/new` (`F2`) needs a provider/model and a resolvable credential environment variable, and creation itself calls no model; the form also has Workspace, Tools (`list_directory,read_file,search_text,find_files,write_file,edit_file,run_command`), initial permission mode, MCP server, "Prompt cache (on | off)", and "Code execution (on | off)" fields (interactive `tars` also accepts `--code-execution` / `--no-code-execution`). F3 reopens a saved session using its original frozen definition and does not apply new global model presets.

The interface uses a single-column conversation layout: the top shows TARS, model and session information; the body distinguishes input from other materials with `❯ You` and `●`; the input area has only top and bottom separators, grows with content up to 6 lines, and is limited by the terminal height. The background and main text follow the terminal colors, warm orange highlights selections, gray is used for auxiliary information, and yellow for errors and confirmations. There is no persistent sidebar, wide and narrow terminals use the same structure, and quit/discard use a separate confirmation view.

The command menu contains `/new`, `/sessions`, `/agents`, `/queue`, `/rename`, `/fork`, `/edit`, `/mode`, `/rules`, `/compact`, `/auto_compact`, `/summary`, `/doctor`, `/init`, `/help`, `/tools`, `/repair`, `/status`, `/open`, `/cancel`, `/retry`, `/export`, `/close`, `/discard` and `/quit`. While the menu is open, input is only used for filtering; to enter body text that starts with `/`, paste it. `/status` shows the detail snapshot taken at open time and can be refreshed by reopening. F2–F7 and the save-recovery shortcuts work in the main view; keys inside menus operate the menu, and Ctrl-Q can still start quitting.

Multi-agent activity surfaces in the status bar and transcript without introducing a second coordinator inside the TUI: `tars-tui` subscribes to `ManagedSession::subscribe_events()` (`SessionEvent`), shows `bg N running` in the footer status line whenever finite background tasks are active (recovering via authoritative `ManagedSession::list_agents()` / `active_finite_background_tasks()` snapshots on `Lagged`), displays `agent: <name> (read-only)` in the top header bar and `viewing agent: <name> (read-only)` in the bottom status bar while inspecting a child agent, and renders incoming `tars:task-notification` blocks compactly (summarizing `<task-notification>` status and agent/operation metadata instead of flooding the viewport with raw XML).

Each session keeps its own uncommitted draft. Switching views and redrawing never cancel work or submit twice; pasting only inserts text, control characters are filtered, and pasting a string such as `/quit` never executes a command. Enter sends in this round; use Ctrl-J for a newline. Ctrl-Q/close asks first when a draft or queued prompt exists; uncommitted drafts and in-memory queued prompts are not part of the automatically saved Context. Execution and save states are shown separately, and Completed does not mean Saved. Historical materials are shown by content and never restore old work tables or execute old tools.

On save failure the owner and write lock are kept and exit is paused; after fixing the directory you can press Ctrl-R, or Ctrl-E to export to the configured recovery directory (current directory by default) and then choose the next step. Export produces `tars-recovery-<uuid>.json` and never overwrites an existing file; export failure is reported separately. Recovery files over 64 MiB are still written completely, with an explicit notice that the current version cannot import them directly. Ctrl-D does not undo records already on disk, and the close report keeps the facts of whether the original commit was applied, not applied, not attempted or still unconfirmable.

When unpaired declarations exist after an interruption, sending keeps the draft and prompts for F7. The material panel first waits for the original work to settle and shows a bounded diagnosis and original batch summary; `a` or `r` only produces a preview, Enter applies and waits for saving, and Esc returns to the draft; for 0.5 seconds after a new preview arrives, Enter and other panel keys are ignored (Esc and scrolling still work) and the notice is dimmed. Switching sessions with F4 during a preview releases the plan; a late result cannot overwrite a new panel. The original work stays Cancelled/TimedOut, and new work is created only when the draft is sent separately. Reopening cannot recover the original batch but can use the removal mode; see [Continuation after interruption](session-continuation.md) for details.

A panic in a background adaptation task only marks the corresponding session, while the interface and other sessions keep running. A terminal read/draw error or a catchable panic restores the terminal mode and then attempts to save; if saving fails it attempts to export the actual materials, finally waits for resources to be released and exits 1, writing failure details to stderr. This is the abnormal cleanup path for losing the interactive surface. An uncatchable hard exit does not guarantee cleanup or recovery of unsaved content.

Rendering slices only cached visible `Line` entries. When the material version changes, the full Context is read once and `Rows` builds wrapped, styled lines (including Markdown parsing and syntax highlighting for assistant segments) on the Tokio blocking pool so draw frames perform zero per-frame Markdown reparsing or re-wrapping; after a read failure it retries at least 1 second later and never retries every frame; when the terminal widens/narrows the cached lines are recomputed in the background while input events are still handled, and `ScrollAnchor` tracks plain-text row projections across rebuilds. At most 64 tasks, and the core separately limits active instances and store concurrency; these counts are not a total memory budget. The current list retains the records seen by this process, F5 adds new records, and opening re-validates the actual record.

The input component currently uses ratatui-textarea 0.9.2, and plain left/right movement and Backspace/Delete adapt to grapheme boundaries of combining characters/emoji; this is not a full IME editor guarantee. PTY tests cover UTF-8, multi-line paste, resize, cancel/close/save faults and terminal restore; a real input-method candidate window, character widths in different terminals and Linux/Windows terminals still need manual/platform verification. Remote CI was not executed in this round, so a local build is not evidence of cross-platform support.

In the earlier two-column prototype's local debug measurements, cached drawing for 100 KiB/1 MiB/8 MiB and 8×1 MiB sessions had a p95 of about 1–3 ms, and 30 draws made no extra full-Context reads. Re-wrapping 8 MiB took about 1.2 seconds, which is a later optimization point; the numbers represent that single local experiment only, and the raw data is in the local prototype validation records (not in this repository).

The terminal captures, wide/narrow window and menu behavior evidence for this round's conversation layout are in the local UI change records (not in this repository). The interface takes inspiration from Claude Code's conversation/input/command interaction and still uses the Ratatui full-screen alternate screen; there is still no native terminal scrollback or broader Claude Code command surface beyond the documented commands, while committed assistant replies and `/summary` now render structured GFM Markdown with syntax highlighting (see [Markdown rendering and syntax highlighting](#markdown-rendering-and-syntax-highlighting)). That record is interface evidence from before the streaming wiring and Markdown rendering.

## Running-turn queue, session management, and external editor

- **Running-turn FIFO queue**: Each open session entry maintains an independent, in-memory bounded FIFO queue (`MAX_QUEUED_PROMPTS = 8`, cleared on reopen and never written to SQLite), keeping `tars-core`'s single-active-work invariant intact. While `entry.busy.is_none()` and a turn is in flight (`entry.turn_in_flight` or `session.status().active_work.is_some()`), submitting non-empty text in the root-agent view without blocking overlays appends the prompt to the queue, clears the editor, and records it in `input_history`; attempts at capacity or while `entry.busy.is_some()` preserve the draft and show a notice. When non-empty, the footer displays `Queued (N): <preview>` (or `Queued (N, paused): <preview>`) with control/BiDi characters escaped via `tars_core::permission::escape_untrusted_text`. Automatic FIFO submission (`submit_text_at(..., false)`, without duplicating `input_history`) runs only after the turn finishes as `completed`, save state is clean (`SaveStatus::Saved`, no `Dirty`/`Saving`/`SaveBlocked`), no unpaired declarations need `/repair`, `Lifecycle::Open` holds, and no modal, approval, trust, repair, or child-agent view is active. Any cancellation, failure, timeout, observation error, `SaveBlocked`, or `/repair` requirement strictly pauses auto-submission (`queue_paused = true`) until cleared or popped. `/queue` (`list`), `/queue pop` (moves the front prompt back into an empty editor), and `/queue clear` manage queued items, and `/close` (`Ctrl-W`) or `/quit` (`Ctrl-Q`) triggers confirmation when queued items remain.
- **Session management (`/rename`, `/fork`, `/sessions` delete)**: `/rename <title>` and `/rename --clear` update or clear the active session's title (`MAX_SESSION_TITLE_CHARS = 160`) via `SessionHost::rename` and sync `entry.title` and `/sessions`. `/fork [title]` calls `SessionHost::fork` on an open, idle, cleanly saved root session, adds the new isolated session to `entries`, and switches to and opens it while leaving the original session intact (refusing busy, saving, save-blocked, or transient sessions). In `/sessions`, `Ctrl-D` or `Delete` opens `Confirmation::DeleteSession` (`y`/`n`) for an unopened, unlocked session (refusing open or busy sessions), while plain printable characters continue filtering `query`.
- **External `$EDITOR` editing (`Ctrl-G` / `/edit`)**: Resolves `$VISUAL` then `$EDITOR` (trimmed non-empty UTF-8; never guesses a fallback editor when unset or blank), parses arguments with quote-aware splitting (single/double quotes and backslash escapes), and spawns directly via `Command::new` without `sh -c`. The current draft is written to an exclusive `tars-prompt-*.md` temporary file whose write descriptor is flushed and closed (`into_temp_path()`) before spawning so atomic-rename editors work cleanly. Before suspending raw mode, alternate screen, and bracketed paste, `App::run` drops `EventStream`, runs the subprocess under a drop guard (`run_with_suspended_terminal`) that unconditionally restores the terminal and clears the screen, and recreates `EventStream::new()`. Edited text is imported (with normalized line endings and reset history cursor) only when exit status is `0`, size is `<= 1 MiB` (`MAX_EDITOR_IMPORT_BYTES`), and content is valid UTF-8; otherwise the original draft is preserved. Blocked overlays and read-only child-agent views are never bypassed.

## Markdown rendering and syntax highlighting

Committed assistant messages and `/summary` panels render as GitHub Flavored Markdown (`pulldown-cmark` 0.13 with `default-features = false` and `ENABLE_TABLES | ENABLE_STRIKETHROUGH | ENABLE_TASKLISTS`), styled solely with the terminal default background, `ACCENT`, `MUTED`, and standard ANSI foreground colors/modifiers so both dark and light terminals remain legible.

- **Segmentation & isolation**: `TranscriptSegment` applies Markdown parsing only to committed `Role::Assistant` message bodies (across the active transcript, expanded history records via `Transcript::from_history_blocks` and `HistoryView::compose()`, and `/agents` read-only child views) and expanded summary briefs. User prompts (`❯ You`), tool call/result summaries, non-prelude `Role::System` blocks, and expanded raw `tars:prelude:*` / `tars:skill` / `tars:task-notification` XML remain unparsed plain text (`PlainBody`). Folded prelude/update/skill/summary/task-notification lines and compaction/history dividers (`── Compacted ... ──`, `↑ N earlier records`, `start of conversation`) retain their `MutedNotice` semantics and styling.
- **Supported elements**: Headings (`H1`–`H6`), nested bold/italic/strikethrough/inline code, deduplicated links (`label (url)` when distinct, omitting duplicate URLs when `label == url`) and image fallbacks (`[img: ...]`), ordered/unordered/task lists (`[ ]` / `[x]`) with multi-level indentation and hanging-indent wrapping, nested blockquotes (`│ `), viewport-adaptive horizontal rules, dynamic-width boxed GFM tables with column alignment (degrading cleanly to stacked row cards below 20 available columns or when box framing cannot fit), and framed fenced/indented code blocks (`╭─ <lang>`, `│ `, `╰──`).
- **Lightweight pure-Rust syntax highlighting**: `crates/tui/src/markdown/highlight.rs` implements a zero-unsafe, single-pass `O(n)` lexical scanner (no regex backtracking) covering 11 language groups: `rust`/`rs`, `typescript`/`ts`/`tsx`/`javascript`/`js`/`jsx`, `python`/`py`, `go`, `sh`/`bash`/`zsh`/`shell`, `json`/`jsonc`, `toml`, `yaml`/`yml`, `sql`, `c`/`cpp`/`c++`/`h`/`hpp`, and `diff`/`patch`. Unknown languages and code blocks exceeding `64 KiB` (`MAX_HIGHLIGHT_BYTES`) fall back linearly to unhighlighted code without dropping lines.
- **Safety, caching & scroll anchor**: All untrusted input (prose, code blocks, fence language tags, link/image metadata, and table cells) is escaped via `tars_core::permission::escape_untrusted_text` plus `\t -> "    "` before entering Ratatui `Span`s, blocking ESC sequences, control characters, BiDi overrides, and line/paragraph separators while preserving CJK text, emoji, and valid newlines. `Rows` builds wrapped styled lines on the Tokio blocking pool so draw frames perform zero per-frame Markdown reparsing, and `ScrollAnchor` (`capture_scroll_anchor` / `restore_scroll_anchor`) matches consecutive plain-text row projections (`Rows::row_text`) within a `±64`-row window across history loads, automatic compaction, and micro-compaction.
- **Detail panels & streaming boundary**: `/tools` (F6) uses structural `ToolDetailMeta` line offsets (immune to string-prefix spoofing in plain file outputs) to color record headers and structurally expand and highlight unified diffs embedded in `write_file`/`edit_file` JSON results (including lazily loaded spilled artifacts) while remaining strictly read-only; `/summary` renders the brief chain as width-adaptive Markdown. During active streaming, `Preview` retains its bounded `O(1)` tail incremental wrapping without reparsing Markdown per delta, switching to full Markdown rendering upon commit.

## Compaction and history display

The status line shows the estimated context size (`ctx 63% / 200k`, or `ctx ~120k` when the window is unknown) and appends `auto off` when automatic compaction is disabled; `/status` additionally shows the retained-work sheet as `Works: used / capacity`. `/auto_compact` without an argument shows the same facts, and an invalid argument leaves the settings unchanged; when the window is unknown it explains that `context_window` must be set in the shared TOML or when creating the session. Live compaction, micro-compaction, and temporary frame-trimming progress events update the session's footer notice area (for example `Micro-compacted 4 tool results: ~142k → ~48k tokens`, `Request frame temporarily trimmed: ~... -> ~... tokens`, or `Fixed prefix too large; compaction skipped`).

The conversation displays the current messages below the expanded history, with the fixed prefix at the top of the transcript. In the current conversation view (`Transcript::from_materials`), `tars:prelude:*` prefix blocks (system contract, custom slots, `AGENTS.md`, `<available_skills>`, `<available_agents>`, `<env>`) are folded into a single summary line (`● Session prelude · <N> blocks · folded`) so large instructions and catalogs do not flood the viewport, mid-session `tars:prelude:update:<sec>` blocks fold to `● Prelude updated (<sec>) · folded`, promoted `tars:skill` blocks preserved across compaction fold to `● Skill preserved (<name>) · folded`, and `tars:task-notification` blocks fold into compact notification summaries (keeping plain non-prelude `Role::System` blocks verbatim). In the expanded history view above (`from_history_blocks`), prelude, update, and skill blocks remain expanded and clearly labeled with their section or skill name and provenance. Opening or reloading reads only the current Context and the small index stored in the record, reading **0** history record files and **0** artifact files on open. `Transcript::from_materials` keeps live `MicroCompact` stubs out of `history_range`, and `HistoryView` (via `ExpansionCursor::new_for_prefix`) skips live `MicroCompact` entries whose stubs remain in the current tail so they neither trigger record reads nor appear in `earlier()`; each micro-compacted tool call/result is therefore shown once in the current conversation as a `cleared preview` (or `spilled preview` when inherited from an entry spill) without duplicating into the history region above. On reopen, put-back and stripped blocks of the `Summarize`/`Merge` history run are hidden from the current part until the newest record is read (when the retained tail fills the screen). Replaced conversation from `Summarize` and `Merge` is shown above the current part via conversation expansion, separated by divider lines such as `Compacted (auto, ~140k -> 6k)`; `MicroCompact` rewrites emit no divider, and if a later `Summarize` swallows micro-compacted stubs, recursive expansion (`Summarize -> MicroCompact`) restores the original tool outputs once in the history region. When the current view does not fill one screen, earlier records are loaded one at a time until it does; scrolling or pressing PageUp at the top loads the next earlier history record in the background and keeps the rows being viewed in place. When the user is scrolled up during active work, both automatic summarization and live micro-compaction preserve the viewed scroll anchor across the live rebuild. Each brief is shown as a divider standing directly after the summarized piece it replaced and before any stripped replies or the retained tail, not as text. The header states how many records remain unread, whether one is loading, or that the conversation start was reached. A record file that is missing or corrupt shows `this history record cannot be read`, and loading continues with the older records. Loaded rows stay for the life of the open session; a record is read once. Rewrite records written during the session are held in memory by the core history store (up to 64 entries) and supplied directly to the view; any index change rebuilds the cursor and replays known records synchronously without reading files. When a running work compacts or micro-compacts automatically or a summary is followed by a merge, every block is shown once and no record file is read.

Each brief in the current chain is folded to one line in the conversation, marked with the `tars:compaction` provenance; `/summary` renders the full text of all briefs in the chain as Markdown, oldest first. `/compact` runs compaction as a session job (the UI never blocks) and then reloads materials and history; the conversation before the replacement remains visible. Older TARS versions cannot read a record that contains history; export and `--load` still handle only the current Context, and exported materials detach artifact references to past history records so the export can be cleanly imported into another session without orphan references.

## Streaming body

Reasoning deltas, body deltas, and streaming tool-call name/argument drafts for OpenAI Chat Completions, OpenAI Responses and Anthropic Messages are displayed at the end of the conversation, marked `Generating · temporary`. While reasoning streams before body text arrives, the preview shows `💭 Thinking…` and up to the last 6 wrapped rows of reasoning text; once body text begins arriving or `ModelOutputReady` arrives, reasoning collapses to a single compact summary line (`💭 Thinking (N chars)` / `💭 Thought (N chars)`). Streaming tool-call drafts appear as compact `⠋ Preparing <name>: <args>` lines until `ModelOutputReady` hands off to formal `ToolProgress`. After the complete model output arrives it can show `Temporary output · awaiting result`; this state does not mean the save succeeded. Incremental token usage is still not shown while streaming.

The preview is independent of the formal material cache, and each session keeps only the current model round of the current work. You can keep editing the next draft, scroll, resize or switch sessions; cancellation still targets the explicit WorkRef. Switching never resubmits; late events for closed or reopened instances are ignored. Sent input is still refreshed from the actual materials, and the preview never fabricates Context.

The UI updates at most every 50 ms and takes at most 128 observations per tick across all instances, rotating to the next instance when that is exceeded. The core channel capacity is 128, each body or reasoning fragment is at most 16 KiB (tool name fragments at most 256 bytes, arguments at most 16 KiB), and the TUI preview keeps at most 256 KiB of body, 64 KiB of reasoning, and 32 tool-call drafts (128 B name / 1024 B arguments per call). Congestion or truncation shows `Preview incomplete`, and the final result still comes from the reliable terminal state and actual Context. A lagging consumer cannot block the model/cancellation, and never loses the original result or save error.

A delta only re-wraps the last two lines; for abnormally long combining-character sequences it looks back at most 4 KiB for a UTF-8 boundary, so temporary wrapping of such pathological clusters may split lines. Widening/narrowing re-wraps this bounded preview; formal history keeps its original cache and is never copied or re-wrapped per delta.

Work completion, failure, cancellation or close removes the temporary preview, and the formal body updates from the finally returned materials, possibly differing from the preview. While saving is blocked, the truly returned materials are still shown and the retry/export/abandon flow applies. Recovery files, export and the Store never contain the preview; unsent drafts are never saved automatically either.

The real segmented HTTP, TestBackend, PTY and resource evidence for this round is in the local streaming wiring records (not in this repository). Local paths and local verification do not mean the registry has published anything or that CI has passed on every platform.

## Tool execution

Workspace and Tools in the new-session form use the core's unified resolution. The body shows a bounded argument summary, Waiting / Running / Returned / Committed, and any governing command-rule provenance (`allowed by ...`, `denied by ...`, `asked by ...`); Returned still awaits material commit, and Committed does not mean the work is done or Saved. Calls are attributed by the current instance, WorkRef, InvocationId and declared BlockId, and identical arguments still count as two independent calls.

Tool events go through the same bounded observation channel and falling behind shows `Tool observations incomplete`, corrected with a reliable summary at the end. After cancellation the actual UnknownOutcome or non-executed fact is shown, and the whole batch is never marked as run. Full results expand from the existing actual material cache: F6 or `/tools`; this never claims the original uncommitted batch, reads workspace files or reruns tools. In `/tools`, record headers (`Declaration ...` / `Result for ...`) are highlighted and unified diffs embedded in `write_file`/`edit_file` results are structurally expanded into readable lines and highlighted via `ToolDetailMeta` line offsets (immune to string-prefix spoofing in plain file outputs). When a committed tool result was spilled at entry to the SQLite `artifacts` table (`artifact:<id>`) or folded by micro-compaction into `history_records` (`<record_id>/<orig_block_id>`, or inheriting `artifact:<id>`), opening the session reads **0** `artifacts` and **0** `history_records` entries and the main conversation displays the preview summary (`spilled preview` or `cleared preview`); only pressing F6 or running `/tools` reads the full original output on demand via `read_artifact` (also expanding and highlighting embedded diffs), notes `"Model sees spilled preview only"` (for `artifact:<id>`) or `"Model sees cleared preview only"` (for `<record_id>/<orig_block_id>`), and falls back cleanly to showing the model-facing preview with an unreadable notice if the record or artifact row cannot be read. Control characters, bidirectional text controls and line/paragraph separators in summaries and full results are escaped only at the display layer, while ordinary Chinese, emoji and newlines are kept as-is; materials in the Store stay as-is.

Tool events update a small state set and never copy or re-wrap the whole Context per event. The cache refreshes only when the material version changes; expanding, scrolling, resizing and switching add no model/tool calls. Detailed limits and platform boundaries are in [Workspace tools](workspace-tools.md).
