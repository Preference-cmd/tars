# TUI prototype

`tars-tui` is the native terminal consumer built on Ratatui + Crossterm and shares the `SessionHost` and the [TOML configuration](configuration.md). It is currently a development prototype: session creation/opening, current materials, temporary streaming body, final result, multi-line input, cancellation, saving and recovery operations are wired; workspace tools (including the write confirmation panel, `/mode` command and `Shift-Tab` mode switching) are wired; MCP is wired through the `mcp.json` configuration with form selection, definition snapshots and runtime tools, the status line reports servers that did not start and tools that were skipped after a session is opened, and a saved full-access that was downgraded to ask on reopen is also reported, while MCP calls support execution, confirmation and rejection according to the permission mode. Long-session compaction is wired: the conversation expands the replaced material above the current materials, reads history records lazily while scrolling up, folds the current summary, and exposes `/auto_compact`, `/compact` and `/summary`. Startup now checks the sandbox backend and the external `rg` before the conversation screen, so search availability is known before the first request (see [Startup check](#startup-check)). There is no GUI or install distribution. Commands run through the built-in `run_command`, described in [Workspace tools](workspace-tools.md); the local command-tool proposal records are not part of this repository. Build and dependency baselines are in [Current implementation](README.md).

The command confirmation panel shows the full command, working directory, deadline, network policy and "workspace writable, `.git` hooks and configuration read-only, credentials unreadable"; a sandbox-outside request instead shows a prominent "not in the sandbox: whole machine readable/writable, network reachable, credentials readable" and the model's justification. `/status` adds `Prompt cache: on | off`, `Commands: ...`, showing the sandbox backend and each capability dimension (with the reason when unavailable), plus `Search: ready (rg <version> at <path>)` or `Search: unavailable: <reason>`, the `Sandbox:` brief from the startup check, and a `Usage:` section with live session call counts, input rounds, token totals, conversation/compaction breakdowns, and last call details (see [Usage statistics](session-lifecycle.md#7-usage-statistics)). The new-session form shows a read-only `Command: network ... · timeout ...` line when Tools includes `run_command`; it is not an input field and cannot be edited. The line disappears once the command tool is disabled.

## Startup check

After the terminal is initialized and before the conversation screen, the TUI runs two checks as blocking background jobs under one bounded deadline: the platform sandbox probe and the external-tool resolution from `[external_tools]`. The splash shows a row for each (`Sandbox`, `ripgrep`) with core's own short report or reason; the checks never block terminal input and a stuck probe is abandoned at the deadline.

- All ready: the main screen opens directly, with no question and no unavailable line.
- Sandbox unavailable: the main screen opens with `search unavailable: <reason>` in the footer, and no download is offered because search needs both.
- `rg` unavailable and configured as `managed`: the splash asks `Download ripgrep 15.2.0 (about 2 MB from github.com/BurntSushi/ripgrep) and install it for search? [y/N]`. For 0.5 seconds after the question appears every key is ignored, the same window as the confirmation and repair panels. `y` shows a downloading state, installs the pinned release through the core, re-resolves the check and enters the main screen; `n`, Esc, a failed install or the deadline enters with the reason.
- `rg` unavailable and configured as `system` or an absolute path: no download is offered; the main screen opens with the reason.

The resolved tools are attached to the session host this TUI opens, so `search_text` runs exactly the checked executable; a declined or failed check still lets sessions open and rejects search calls with the core reason. `/status` keeps the `Search:` and `Sandbox:` lines for the running session. The check and the consent gate live in core (`tars_core::external_tools`, `tars_core::sandbox`); the TUI only presents progress and collects the answer, and the 15-second startup deadline is a presentation bound, not a core contract.

```sh
cargo build -p tars-tui --locked
./target/debug/tars-tui --config /path/to/config.toml
# Without the global configuration, fill in the model in the new-session form:
./target/debug/tars-tui --no-config --store ./tars-data
```

Both stdin and stdout must be interactive terminals. At least 30×12; below that size the whole screen shows only a resize notice. When a confirmation request is pending, at least 30×19 is needed to show the panel and accept allow/reject keys; when smaller, only the resize notice is shown and Esc or Ctrl-C still cancels the round. In a short window the form shows the current field at a time, with Tab switching. Creating a session needs a provider/model and a resolvable credential environment variable, and creation itself calls no model; the form also has Workspace, Tools, initial permission mode, MCP server, and "Prompt cache (on | off)" fields. F3 reopens a saved session using its original frozen definition and does not apply new global model presets.

The interface uses a single-column conversation layout: the top shows TARS, model and session information; the body distinguishes input from other materials with `❯ You` and `●`; the input area has only top and bottom separators, grows with content up to 6 lines, and is limited by the terminal height. The background and main text follow the terminal colors, warm orange highlights selections, gray is used for auxiliary information, and yellow for errors and confirmations. There is no persistent sidebar, wide and narrow terminals use the same structure, and quit/discard use a separate confirmation view.

The command menu contains `/new`, `/sessions`, `/mode`, `/help`, `/status`, `/tools`, `/repair`, `/open`, `/cancel`, `/retry`, `/export`, `/compact`, `/auto_compact`, `/summary`, `/close`, `/discard` and `/quit`. While the menu is open, input is only used for filtering; to enter body text that starts with `/`, paste it. `/status` shows the detail snapshot taken at open time and can be refreshed by reopening. F2–F7 and the save-recovery shortcuts work in the main view; keys inside menus operate the menu, and Ctrl-Q can still start quitting.

Each session keeps its own uncommitted draft. Switching views and redrawing never cancel work or submit twice; pasting only inserts text, control characters are filtered, and pasting a string such as `/quit` never executes a command. Enter sends in this round; use Ctrl-J for a newline. Ctrl-Q/close asks first when a draft exists; uncommitted drafts are not part of the automatically saved Context. Execution and save states are shown separately, and Completed does not mean Saved. Historical materials are shown by content and never restore old work tables or execute old tools.

On save failure the owner and write lock are kept and exit is paused; after fixing the directory you can press Ctrl-R, or Ctrl-E to export to the configured recovery directory (current directory by default) and then choose the next step. Export produces `tars-recovery-<uuid>.json` and never overwrites an existing file; export failure is reported separately. Recovery files over 64 MiB are still written completely, with an explicit notice that the current version cannot import them directly. Ctrl-D does not undo records already on disk, and the close report keeps the facts of whether the original commit was applied, not applied, not attempted or still unconfirmable.

When unpaired declarations exist after an interruption, sending keeps the draft and prompts for F7. The material panel first waits for the original work to settle and shows a bounded diagnosis and original batch summary; `a` or `r` only produces a preview, Enter applies and waits for saving, and Esc returns to the draft; for 0.5 seconds after a new preview arrives, Enter and other panel keys are ignored (Esc and scrolling still work) and the notice is dimmed. Switching sessions with F4 during a preview releases the plan; a late result cannot overwrite a new panel. The original work stays Cancelled/TimedOut, and new work is created only when the draft is sent separately. Reopening cannot recover the original batch but can use the removal mode; see [Continuation after interruption](session-continuation.md) for details.

A panic in a background adaptation task only marks the corresponding session, while the interface and other sessions keep running. A terminal read/draw error or a catchable panic restores the terminal mode and then attempts to save; if saving fails it attempts to export the actual materials, finally waits for resources to be released and exits 1, writing failure details to stderr. This is the abnormal cleanup path for losing the interactive surface. An uncatchable hard exit does not guarantee cleanup or recovery of unsaved content.

Rendering uses only cached visible lines. When the material version changes, the full Context is read once and text and line-wrap indexes are generated in the background; after a read failure it retries at least 1 second later and never retries every frame; when the terminal widens/narrows the indexes are recomputed while input events are still handled. At most 64 tasks, and the core separately limits active instances and store concurrency; these counts are not a total memory budget. The current list retains the records seen by this process, F5 adds new records, and opening re-validates the actual record.

The input component currently uses ratatui-textarea 0.9.2, and plain left/right movement and Backspace/Delete adapt to grapheme boundaries of combining characters/emoji; this is not a full IME editor guarantee. PTY tests cover UTF-8, multi-line paste, resize, cancel/close/save faults and terminal restore; a real input-method candidate window, character widths in different terminals and Linux/Windows terminals still need manual/platform verification. Remote CI was not executed in this round, so a local build is not evidence of cross-platform support.

In the earlier two-column prototype's local debug measurements, cached drawing for 100 KiB/1 MiB/8 MiB and 8×1 MiB sessions had a p95 of about 1–3 ms, and 30 draws made no extra full-Context reads. Re-wrapping 8 MiB took about 1.2 seconds, which is a later optimization point; the numbers represent that single local experiment only, and the raw data is in the local prototype validation records (not in this repository).

The terminal captures, wide/narrow window and menu behavior evidence for this round's conversation layout are in the local UI change records (not in this repository). The interface takes inspiration from Claude Code's conversation/input/command interaction and still uses the Ratatui full-screen alternate screen; there is no native terminal scrollback, Markdown rendering or other Claude Code command capabilities yet. That record is interface evidence from before the streaming wiring.

## Compaction and history display

The status line shows the estimated context size (`ctx 63% / 200k`, or `ctx ~120k` when the window is unknown) and appends `auto off` when automatic compaction is disabled; `/status` additionally shows the retained-work sheet as `Works: used / capacity`. `/auto_compact` without an argument shows the same facts, and an invalid argument leaves the settings unchanged; when the window is unknown it explains that `context_window` must be set in the shared TOML or when creating the session.

The conversation always shows the current Context in full. Replaced conversation is shown above it via conversation expansion, separated by divider lines such as `Compacted (auto, ~140k -> 6k)`. Opening or reloading reads only the current Context and the small index stored in the record, reading 0 record files on open. When the current Context does not fill one screen, earlier records are loaded one at a time until it does; scrolling or pressing PageUp at the top loads the next earlier history record in the background and keeps the rows being viewed in place. Each brief is shown as a divider after the originals it replaced, not as text. The header states how many records remain unread, whether one is loading, or that the conversation start was reached. A record file that is missing or corrupt shows `this history record cannot be read`, and loading continues with the older records. Loaded rows stay for the life of the open session; a record is read once. Material replaced by a live compaction is adopted from the rows already on screen without reading files; a rewrite that the view cannot adopt (for example several at once) restarts the lazy expansion. When a running work compacts automatically, the material version change refreshes the index and the older rows stay visible.

The current summary block is folded to one line in the conversation, marked with the `tars:compaction` provenance; `/summary` shows its full text in a panel. `/compact` runs compaction as a session job (the UI never blocks) and then reloads materials and history; the conversation before the replacement remains visible. Older TARS versions cannot read a record that contains history; export and `--load` still handle only the current Context.

## Streaming body

Body deltas for OpenAI Chat Completions, OpenAI Responses and Anthropic Messages are displayed at the end of the conversation, marked `Generating · temporary`. After the complete model output arrives it can show `Temporary output · awaiting result`; this state does not mean the save succeeded. Currently only the body is previewed, not reasoning, tool-argument drafts or incremental usage.

The preview is independent of the formal material cache, and each session keeps only the current model round of the current work. You can keep editing the next draft, scroll, resize or switch sessions; cancellation still targets the explicit WorkRef. Switching never resubmits; late events for closed or reopened instances are ignored. Sent input is still refreshed from the actual materials, and the preview never fabricates Context.

The UI updates at most every 50 ms and takes at most 128 observations per tick across all instances, rotating to the next instance when that is exceeded. The core channel capacity is 128, each body is at most 16 KiB, and the TUI body preview is at most 256 KiB. Congestion or truncation shows `Preview incomplete`, and the final result still comes from the reliable terminal state and actual Context. A lagging consumer cannot block the model/cancellation, and never loses the original result or save error.

A delta only re-wraps the last two lines; for abnormally long combining-character sequences it looks back at most 4 KiB for a UTF-8 boundary, so temporary wrapping of such pathological clusters may split lines. Widening/narrowing re-wraps this bounded preview; formal history keeps its original cache and is never copied or re-wrapped per delta.

Work completion, failure, cancellation or close removes the temporary preview, and the formal body updates from the finally returned materials, possibly differing from the preview. While saving is blocked, the truly returned materials are still shown and the retry/export/abandon flow applies. Recovery files, export and the Store never contain the preview; unsent drafts are never saved automatically either.

The real segmented HTTP, TestBackend, PTY and resource evidence for this round is in the local streaming wiring records (not in this repository). Local paths and local verification do not mean the registry has published anything or that CI has passed on every platform.

## Tool execution

Workspace and Tools in the new-session form use the core's unified resolution. The body shows a bounded argument summary and Waiting / Running / Returned / Committed; Returned still awaits material commit, and Committed does not mean the work is done or Saved. Calls are attributed by the current instance, WorkRef, InvocationId and declared BlockId, and identical arguments still count as two independent calls.

Tool events go through the same bounded observation channel and falling behind shows `Tool observations incomplete`, corrected with a reliable summary at the end. After cancellation the actual UnknownOutcome or non-executed fact is shown, and the whole batch is never marked as run. Full results expand from the existing actual material cache: F6 or `/tools`; this never claims the original uncommitted batch, reads files or reruns tools. Control characters, bidirectional text controls and line/paragraph separators in summaries and full results are escaped only at the display layer, while ordinary Chinese, emoji and newlines are kept as-is; materials in the Store stay as-is.

Tool events update a small state set and never copy or re-wrap the whole Context per event. The cache refreshes only when the material version changes; expanding, scrolling, resizing and switching add no model/tool calls. Detailed limits and platform boundaries are in [Workspace tools](workspace-tools.md).
